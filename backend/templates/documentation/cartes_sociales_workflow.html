Workflow Cartes Sociales

Vue d'ensemble

Le système de Cartes Sociales permet de gérer des consommations subventionnées pour les populations vulnérables via des tickets de bidons d'eau à tarif réduit.

Principe de fonctionnement

Les bénéficiaires de cartes sociales peuvent collecter de l'eau gratuitement ou à prix réduit via des bidons standardisés de 20 litres. Chaque retrait est enregistré sur un ticket qui sera ensuite traité et validé.

20 L
Par bidon (constante)

Avantage : Le volume consommé via carte sociale est automatiquement déduit de la facture volumétrique du kiosque, évitant une double facturation.

Modèle CarteSociale

Représente une carte sociale attribuée à un bénéficiaire pour un point d'eau spécifique.

Champ Type Description
id UUIDField Identifiant unique de la carte
numero_carte CharField(50) Numéro de la carte physique (optionnel)
nom_beneficiaire CharField(255) Nom du bénéficiaire
ouvrage ForeignKey(Ouvrage) Ouvrage lié à la carte
point_eau ForeignKey(PointEau) Point d'eau spécifique (kiosque)
nombre_habitants IntegerField Nombre de personnes dans le foyer (défaut 4)
date_creation DateField Date de création de la carte
date_expiration DateField Date d'expiration (optionnelle)
statut CharField active / suspendue / expiree / annulee

Relations

  • Ouvrage : Chaque carte est liée à un ouvrage (infrastructure d'eau)
  • Point d'eau : Chaque carte est liée à un kiosque spécifique
  • Consommations : Une carte peut avoir plusieurs consommations mensuelles

Modèle ConsoCarteSociale

Enregistre chaque consommation d'un bénéficiaire de carte sociale (ticket traité).

Champ Type Description
id UUIDField Identifiant unique
releve ForeignKey(Releve) Relevé du kiosque associé (pour déduction)
carte_sociale ForeignKey(CarteSociale) Carte sociale concernée
quantite_bidons IntegerField Nombre de bidons de 20L consommés
volume_total FloatField Volume en m³ (auto-calculé : quantité × 20L / 1000)
date DateField Date de la facture/ticket
montant_paye DecimalField Montant payé par le bénéficiaire (si tarif réduit)
photo TextField Photo du ticket rempli (base64 ou URL)
numeroDiameX CharField(50) Numéro de pièce DiameX (si exporté)
baseDiameX CharField(50) Prog/Base DiameX

Calcul automatique du volume

Le champ volume_total est calculé automatiquement lors de la sauvegarde :

volume_total = (quantite_bidons × 20L) / 1000

Exemple : 10 bidons = (10 × 20) / 1000 = 0.2 m³

Workflow détaillé étape par étape

1 Création de la carte sociale

  • Identification du bénéficiaire éligible
  • Attribution d'une carte sociale liée à :
    • Un ouvrage spécifique
    • Un point d'eau (kiosque)
  • Saisie du nombre d'habitants du foyer (défaut 4)
  • Statut initial : active
  • Possibilité de définir une date d'expiration

Exemple :

CarteSociale.objects.create(
    numero_carte='CS-2025-001',
    nom_beneficiaire='Marie RASOLOFO',
    ouvrage=ouvrage_obj,
    point_eau=kiosque_obj,
    nombre_habitants=6,
    statut='active'
)

2 Retrait de bidons par le bénéficiaire

  • Le bénéficiaire se présente au kiosque avec sa carte
  • Le gérant du kiosque remet X bidons de 20L
  • Remplissage d'un ticket papier avec :
    • Nom du bénéficiaire
    • Numéro de carte (si disponible)
    • Nombre de bidons remis
    • Date du retrait
    • Signature du bénéficiaire
  • Le ticket physique est conservé pour traitement ultérieur

Volume standard par bidon :

20 litres (constante dans le système)

Cette valeur est figée dans le code et ne peut pas être modifiée par l'utilisateur.

3 Saisie dans l'interface web

  • La caissière accède au module : Plannings → Cartes Sociales
  • Sélection de l'ouvrage dans la liste déroulante
  • Affichage automatique de :
    • L'organisation gestionnaire
    • Le tarif carte sociale configuré
    • La liste des points d'eau avec leurs cartes actives
  • Pour chaque carte :
    • Saisir le nombre de bidons
    • Uploader la photo du ticket
    • Le système calcule automatiquement le montant selon le tarif
  • Validation et création de ConsoCarteSociale
Le tarif carte sociale est défini au niveau de l'organisation gestionnaire. Il peut être 0 (gratuit) ou un montant fixe par bidon.

4 Création de la consommation

  • Appel API : POST /billing/cartes-sociales/api/imprimer-ticket/
  • Création d'une ligne ConsoCarteSociale :

Données enregistrées :

ConsoCarteSociale.objects.create(
    carte_sociale=carte_obj,
    quantite_bidons=15,
    volume_total=(15 × 20) / 1000,  # 0.3 m³ (auto-calculé)
    date='2025-01-15',
    montant_paye=tarif × 15,  # Si tarif défini
    photo='data:image/png;base64,...'  # Photo uploadée
)
Le volume est automatiquement calculé par la méthode save() du modèle. Pas besoin de le saisir manuellement.

5 Déduction du relevé du kiosque

  • Lors de la saisie du relevé mensuel du kiosque
  • Le système récupère le volume total des cartes sociales du mois : 
    volume_carte_sociale = ConsoCarteSociale.objects.filter(
    carte_sociale__point_eau=point_eau,
    date__month=mois,
    date__year=annee
).aggregate(total=Sum('volume_total'))['total']
  • Ce volume est déduit automatiquement de la facture volumétrique :
    • volume_facture = consommation - volume_carte_sociale - volume_non_facture
  • Le kiosque ne paie que le volume consommé hors cartes sociales

Exemple de déduction :

Consommation totale kiosque : 15 m³

Volume cartes sociales : -3.5 m³ (175 bidons)

Volume non facturé (fuites) : -0.5 m³

Volume facturé au kiosque : 11 m³ ✅

6 Export vers DiameX (comptabilité)

  • Les consommations de cartes sociales peuvent être exportées vers DiameX
  • Chaque ligne ConsoCarteSociale génère une transaction comptable
  • Le champ numeroDiameX est renseigné après export réussi
  • Permet de suivre les subventions allouées aux cartes sociales
À implémenter : L'export automatique vers DiameX pour les cartes sociales n'est pas encore développé. Les champs numeroDiameX et baseDiameX sont prêts mais non utilisés.

Analyse et statistiques

Module d'analyse permettant de suivre la consommation des cartes sociales avec des indicateurs clés.

Indicateurs disponibles

Nombre de cartes actives

Nombre total de cartes sociales avec statut='active' dans la zone géographique filtrée.

Population couverte

Somme du champ nombre_habitants de toutes les cartes actives. Si non renseigné, compte 4 personnes par défaut.

Volume total annuel

Somme des volume_total de toutes les consommations de l'année. Exprimé en m³.

Montant total annuel

Somme des montant_paye de toutes les consommations. Représente la contribution des bénéficiaires.

Consommation moyenne par carte

Volume total annuel / Nombre de cartes actives. Exprimé en m³/carte/an.

Consommation habitant/jour

(Volume annuel × 1000) / Population / 365
Exprimé en litres/habitant/jour (L/hab/j)

Évolution mensuelle

Le module d'analyse affiche des graphiques Chart.js avec :

  • Volume par mois : Évolution de la consommation sur 12 mois
  • Montant par mois : Contribution des bénéficiaires si tarif appliqué
  • Nombre de cartes actives par mois : Croissance du programme

Filtres disponibles

Les statistiques peuvent être filtrées par :

  • Région → District → Commune → Village
  • Ouvrage spécifique
  • Année (année courante par défaut)

Règles CRITICAL

1. Volume bidon FIGÉ à 20 litres

La constante VOLUME_BIDON_LITRES = 20.0 est définie dans le modèle et ne peut PAS être modifiée par l'interface utilisateur. Tous les bidons font exactement 20 litres.

2. Calcul automatique du volume total

Le champ volume_total est automatiquement calculé par la méthode save() du modèle ConsoCarteSociale. Ne jamais le saisir manuellement.

volume_total = (quantite_bidons × 20L) / 1000

3. Population par défaut = 4 personnes

Si le champ nombre_habitants n'est pas renseigné ou vaut 0, le système compte automatiquement 4 personnes par foyer pour les statistiques.

4. Déduction automatique du relevé kiosque

Le volume consommé via cartes sociales est automatiquement déduit de la facture volumétrique du kiosque. Pas de double facturation.

volume_facture = consommation - volume_carte_sociale - volume_non_facture

5. Photo du ticket OBLIGATOIRE

Chaque consommation doit être justifiée par une photo du ticket rempli. Le champ photo stocke l'image en base64 ou URL.

6. Tarif carte sociale au niveau organisation

Le tarif appliqué (gratuit ou payant) est défini dans Organisation.tarif_carte_sociale. Il s'applique à toutes les cartes de cette organisation.

FAQ - Questions fréquentes

1. Peut-on modifier le volume d'un bidon (20L) ?

Non. Le volume de 20 litres par bidon est une constante définie dans le code (VOLUME_BIDON_LITRES = 20.0). Cette valeur ne peut pas être modifiée via l'interface utilisateur pour garantir l'uniformité du système.

2. Que se passe-t-il si le nombre d'habitants n'est pas renseigné ?

Le système compte automatiquement 4 personnes par foyer pour les statistiques de population couverte et de consommation par habitant.

3. Comment éviter la double facturation avec le kiosque ?

Le volume consommé via cartes sociales est automatiquement déduit du relevé volumétrique du kiosque lors de la saisie du relevé mensuel. Le champ volume_carte_sociale du modèle Releve stocke cette déduction.

4. Le service peut-il être gratuit ou payant ?

Les deux. Le tarif est défini dans Organisation.tarif_carte_sociale. S'il vaut 0, le service est gratuit. Sinon, c'est le prix par bidon que le bénéficiaire doit payer.

5. Peut-on consulter l'historique des consommations d'une carte ?

Oui, via la relation inverse carte.consommations.all() qui retourne toutes les lignes ConsoCarteSociale liées à cette carte, avec les dates et volumes.

6. Comment gérer l'expiration d'une carte ?

Le champ date_expiration permet de définir une date limite. Le statut peut être changé manuellement en expiree. Les cartes expirées ne sont pas listées dans l'interface de saisie (filtre statut='active').
