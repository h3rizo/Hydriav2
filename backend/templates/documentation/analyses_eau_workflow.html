Documentation - Workflow Analyses d'Eau

Guide complet du système d'analyse de qualité de l'eau et validation par packs

Vue d'ensemble du module Analyses d'Eau

Le module Analyses d'Eau permet de documenter, suivre et valider la qualité de l'eau distribuée par les différents ouvrages et équipements. Il intègre un système unique de validation par packs journaliers qui garantit la fiabilité des résultats d'analyse en vérifiant la présence de témoins positifs et négatifs.
⚠️ RÈGLE CRITIQUE : Toutes les analyses effectuées le même jour (même date_analyse) constituent un pack. Un pack contaminé (témoin négatif positif) invalide TOUTES ses analyses, même celles qui semblaient problématiques.

Objectifs principaux

  • Qualité de l'eau : Détecter les contaminations microbiologiques (coliformes)
  • Validation du processus : Système de témoins positifs/négatifs pour garantir la fiabilité
  • Traçabilité : Historique complet avec dates de prélèvement, analyse et résultat
  • Géolocalisation : Lien avec communes, ouvrages, équipements et points d'eau
  • Statistiques par pack : Dashboard avec indicateurs par jour d'analyse

Types de Prélèvement et leur Rôle

Chaque type de prélèvement a un rôle spécifique dans le processus de validation de la qualité de l'eau. Le système distingue 5 types principaux, dont 2 sont des témoins de contrôle.
Type Code Rôle Résultat Attendu Conséquence si Non Conforme
Point d'eau traditionnel point_eau_traditionnel 🔬 TÉMOIN POSITIF DOIT contenir des coliformes Pack INDÉTERMINÉ (processus non validé)
Point d'eau point_eau 🚰 Échantillon réel NE DOIT PAS contenir de coliformes Pack PROBLÉMATIQUE (contamination réelle)
Équipement equipement ⚙️ Échantillon réel NE DOIT PAS contenir de coliformes Pack PROBLÉMATIQUE (contamination réelle)
Bouteille bouteille 🧪 TÉMOIN NÉGATIF NE DOIT JAMAIS contenir de coliformes Pack CONTAMINÉ (tout est invalide)
Autre autre 🔍 Échantillon spécial Selon contexte Évaluation au cas par cas
💡 Note : Un pack terrain typique contient :
  • 1 témoin positif (point d'eau traditionnel non aménagé)
  • 1 témoin négatif (bouteille d'eau contrôle)
  • N échantillons réels (points d'eau, équipements à analyser)

Statuts de Pack (Ordre de Priorité)

Le système calcule automatiquement le statut de chaque pack en analysant toutes les analyses effectuées le même jour. Les statuts suivent un ordre de priorité strict, du plus grave au plus favorable.

1 ❌ CONTAMINÉ

Condition : Coliformes détectés sur la bouteille (témoin négatif)
Signification : Le processus d'analyse lui-même est contaminé
Conséquence : TOUT le pack est invalide, refaire l'analyse complète avec matériel stérile neuf
Fiabilité : Aucune analyse de ce pack n'est fiable
⚠️ IMPORTANT : Si le témoin négatif est contaminé, même les points d'eau qui montrent des coliformes peuvent être des faux positifs dus à la contamination du processus.

2 ⚠️ PROBLÉMATIQUE

Condition : Coliformes sur équipement/point d'eau + bouteille propre
Signification : Contamination réelle de l'eau distribuée
Conséquence : Intervention requise (désinfection, réparation)
Fiabilité : Résultat fiable (processus validé par témoin négatif)
Exemples de causes : - Infiltration d'eau de surface dans l'ouvrage - Contamination du réseau de distribution - Défaillance du système de traitement - Robinet/équipement non désinfecté

3 ✅ VALIDE

Condition : Témoin positif présent + bouteille propre + aucun problème équipement/PE
Signification : Processus validé ET eau de bonne qualité
Conséquence : Résultats fiables, aucune action requise
Fiabilité : Maximale (double validation)

4 ❓ INDÉTERMINÉ

Condition : Pas de témoin positif dans le pack
Signification : Processus non validé (manque contrôle qualité)
Conséquence : Résultats non certifiés
Fiabilité : Inconnue
⚠️ Recommandation : Toujours inclure un témoin positif dans chaque pack terrain pour valider le processus d'analyse.

Étapes Critiques

  • Prélèvement : Toujours inclure témoin positif + témoin négatif dans chaque sortie terrain
  • Transport : Conserver les échantillons au frais (< 10°C) et à l'abri de la lumière
  • Délai : Analyse dans les 24h maximum après prélèvement
  • Stérilité : Utiliser matériel stérile neuf pour chaque échantillon
  • Traçabilité : Noter date/heure prélèvement, lieu exact, conditions météo

Logique de Validation par Packs

Le système agrège automatiquement toutes les analyses effectuées le même jour (date_analyse identique) pour calculer le statut du pack selon l'algorithme suivant :

Algorithme de Calcul (Ordre de Priorité)

# Fichier : backend/apps/inspections/views_analyse_eau_packs.py

def calculer_statut_pack(analyses_du_jour):
    """
    Calcule le statut d'un pack d'analyses
    Ordre de priorité : CONTAMINÉ > PROBLÉMATIQUE > VALIDE > INDÉTERMINÉ
    """

    # 1. Vérifier contamination du témoin négatif (PRIORITÉ MAX)
    bouteilles = analyses_du_jour.filter(type_prelevement='bouteille')
    for bouteille in bouteilles:
        if bouteille.nombre_coliformes and bouteille.nombre_coliformes > 0:
            return 'CONTAMINÉ'  # ← Tout est invalide

    # 2. Vérifier contaminations réelles (équipements/points d'eau)
    contamines = analyses_du_jour.filter(
        type_prelevement__in=['equipement', 'point_eau'],
        nombre_coliformes__gt=0
    ).exists()
    if contamines:
        return 'PROBLÉMATIQUE'  # ← Intervention requise

    # 3. Vérifier présence témoin positif
    temoin_positif = analyses_du_jour.filter(
        type_prelevement='point_eau_traditionnel',
        nombre_coliformes__gt=0
    ).exists()

    if temoin_positif:
        return 'VALIDE'  # ← Processus validé + eau OK
    else:
        return 'INDÉTERMINÉ'  # ← Pas de validation du processus

Recoupement Analyse vs. Planning

-- Requête SQL : Vérifier cohérence analyses saisies vs. plannings terrain

SELECT
    p.date AS date_planning,
    COUNT(DISTINCT ae.id) AS nb_analyses_saisies,
    pd.quantite AS nb_analyses_prevues,
    (COUNT(DISTINCT ae.id) - pd.quantite) AS ecart
FROM plannings p
INNER JOIN planningdetails pd ON pd.planning_id = p.id
INNER JOIN designations d ON pd.designation_id = d.id
LEFT JOIN analyses_eau ae ON DATE(ae.date_prelevement) = p.date
WHERE d.nom ILIKE '%analyse%eau%'
  AND p.date BETWEEN '2025-01-01' AND '2025-12-31'
GROUP BY p.date, pd.quantite
HAVING COUNT(DISTINCT ae.id) != pd.quantite
ORDER BY p.date DESC;
⚠️ Cas d'écarts fréquents :
  • Échantillon contaminé : Analyse refaite → 2 analyses pour 1 planning
  • Équipement inaccessible : Analyse non faite → 0 analyse pour 1 planning
  • Découverte terrain : Analyse supplémentaire non prévue
→ Justifier les écarts dans les observations du planning

1. Import/Export Excel

Le système permet l'import massif d'analyses depuis un fichier Excel pour faciliter la saisie après le terrain. 
# Format Excel requis (colonnes A-K) :
A: Type prélèvement (point_eau, equipement, bouteille, point_eau_traditionnel, autre)
B: Date prélèvement (DD/MM/YYYY HH:MM ou YYYY-MM-DD HH:MM)
C: Date analyse (DD/MM/YYYY HH:MM ou YYYY-MM-DD HH:MM)
D: Date résultat (DD/MM/YYYY HH:MM ou YYYY-MM-DD HH:MM)

J: ID Point d'eau (UUID si type=point_eau)

2. Gestion des Timestamps Dupliqués

💡 Problème résolu (23 décembre 2025) : Excel peut générer des timestamps dupliqués lors de conversions (ex: 2012-10-03 00:00:00 17:10:00).

Solution : Fonction parse_datetime_flexible() qui :
  • Détecte objets datetime natifs d'Excel
  • Nettoie timestamps dupliqués en séparant date et heure
  • Supporte 3 formats : DD/MM/YYYY, YYYY-MM-DD, YYYY-MM-DD HH:MM:SS
  • Retourne datetime naïf localisé avec tz_madagascar.localize()

3. Suppression Complète (Réimport)

🚨 DANGER : L'API /api/analyses-eau/delete-all/ supprime TOUTES les analyses de la base de données.
Utilisation : Uniquement pour réimport complet après correction fichier Excel
Recommandation : Faire backup PostgreSQL avant suppression massive

Dépannage et Problèmes Courants

Problème 1 : Modal "Modifier" ne charge pas les valeurs

Symptôme : Modal s'ouvre mais dropdowns vides
Cause : API ne retourne pas commune_id et ouvrage_id
Solution : API /api/<id>/ enrichie pour inclure ces champs (24 déc 2025)

Problème 2 : Cascade dropdowns ne fonctionne pas

Symptôme : Sélection commune ne charge pas les ouvrages
Cause : Manque event listeners ou URLs incorrectes
Solution : Vérifier JavaScript analyses_eau_v4.js lignes 610-662

Problème 3 : Dates décalées d'un jour

Symptôme : Date Excel "2025-01-01" affichée "2024-12-31"
Cause : Timezone UTC au lieu de Madagascar
Solution : Toujours utiliser tz_madagascar.localize() et .astimezone(tz_madagascar)

Problème 4 : Import Excel échoue

# Erreurs fréquentes :

1. "Format de date invalide"
   → Vérifier format : DD/MM/YYYY HH:MM ou YYYY-MM-DD HH:MM
   → Pas de formats mixtes dans le même fichier

2. "Équipement introuvable"
   → ID doit être UUID valide (8-4-4-4-12 caractères)
   → Vérifier dans table equipements_constitutifs

3. "Colonne manquante"
   → Template Excel : 11 colonnes A-K obligatoires
   → Pas d'espaces dans les noms de colonnes

4. "TNC doit être OUI/NON"
   → Valeurs acceptées : OUI, NON, O, N (insensible casse)
   → Pas de 1/0 ni TRUE/FALSE
