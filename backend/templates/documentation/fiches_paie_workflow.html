Workflow Fiches de Paie - Impression & Export DiameX

  • Documentation
  • Fiches de Paie

Vue d'ensemble

Le module Fiches de Paie gère l'impression des bulletins de salaire mensuels et leur export automatique vers le système comptable DiameX. Ce workflow garantit que chaque fiche de paie est imprimée en double exemplaire (un pour l'employé, un pour l'archive) et que les données salariales sont transmises au service comptabilité sans ressaisie manuelle.

Le système utilise un marquage d'impression irréversible : une fois qu'une fiche est marquée comme imprimée, elle ne peut plus être réimprimée (pour éviter les doublons et garantir la traçabilité). Simultanément, une ligne est créée dans la table temporaire DiameXTemporaire avec toutes les informations nécessaires à l'intégration comptable (compte salaire, montant arrondi, volet budgétaire, etc.).

Ce workflow strict assure la cohérence entre les données RH (salaires payés) et la comptabilité (dépenses enregistrées), tout en réduisant les risques d'erreurs liés à la double saisie.

Étapes Détaillées du Workflow

1 Création de la grille de salaire mensuelle

Description

La grille de salaire est créée chaque mois par le service RH pour calculer les salaires de tous les employés d'une organisation. Elle contient les éléments de rémunération (salaire de base, primes, indemnités) et les retenues (CNAPS, IRSA, avances).

Champs principaux

  • Mois et année : Période de paie (ex: Novembre 2025)
  • Organisation : Soakoja, SHAMA, etc.
  • Base DiameX : Base comptable pour l'export
  • Employés inclus : Liste des employés actifs de l'organisation
  • Statut : À traiter / Validée
Prérequis : Les employés doivent avoir un poste assigné avec un compte_salaire défini pour permettre l'export vers DiameX ultérieurement.
2 Création des paiements depuis la grille

Description

Une fois la grille validée, le RH crée les paiements individuels (modèle Salaire) pour chaque employé. Cette action génère une fiche de paie avec le détail des éléments de rémunération et le salaire net à payer.

Données du paiement

  • Employé : Lien vers le modèle Employe
  • Grille de salaire : Lien vers la grille mensuelle
  • Salaire brut : Montant avant retenues
  • Retenues : CNAPS, IRSA, avances, etc.
  • Salaire net : Montant à verser à l'employé
  • Date de paiement : Généralement le 1er du mois
  • Statut : Automatiquement "Payé" à la création

Automatisations

  • fiche_imprimee initialisé à False
  • date_impression initialisé à None
  • Le salaire apparaît dans la liste "Fiches de Paie Mensuelles"
Important : Seuls les paiements avec statut "Payé" et fiche_imprimee=False sont affichés dans la liste d'impression. Une fois imprimée, la fiche disparaît automatiquement.
3 Sélection des fiches à imprimer

Description

L'utilisateur accède à la page Plannings > Paie > Fiches de Paie Mensuelles et utilise les filtres pour afficher uniquement les fiches qu'il souhaite imprimer.

Filtres disponibles

  • Mois : Sélection du mois de paie (ex: Novembre 2025)
  • Organisation : Soakoja, SHAMA, ou toutes
  • Base DiameX : Filtrer par base comptable
  • Recherche textuelle : Chercher par nom ou surnom d'employé

Sélection multiple

  • Checkbox "Tout sélectionner" pour cocher toutes les fiches visibles
  • Checkbox individuelle pour chaque fiche
  • Compteur dynamique : "X fiche(s) sélectionnée(s)"
Astuce : Si vous avez beaucoup d'employés, filtrez par organisation ou utilisez la recherche pour trouver rapidement une fiche spécifique.
4 Impression des fiches en 2 exemplaires

Description

Après avoir sélectionné les fiches, l'utilisateur clique sur le bouton "Imprimer les fiches sélectionnées". Une confirmation demande s'il souhaite bien imprimer X fiche(s) en 2 exemplaires.

Processus d'impression

  1. Confirmation popup : "Imprimer X fiche(s) en 2 exemplaires ?"
  2. Ouverture d'une nouvelle page avec toutes les fiches sélectionnées
  3. Message d'alerte visible à l'écran (masqué à l'impression) :
    N'oubliez pas d'imprimer chaque fiche en 2 exemplaires !
  4. Déclenchement de la boîte de dialogue d'impression du navigateur
  5. Impression physique sur l'imprimante (répéter 2 fois si nécessaire)

Présentation des fiches

  • Une fiche par page (saut de page automatique)
  • En-tête avec logo entreprise et nom organisation
  • Informations employé : Nom, poste, volet, période
  • Tableau détaillé : Éléments de salaire + Retenues
  • Salaire net en évidence avec fond coloré
  • Signatures : Employé / RH / Direction
CRITICAL : Ne fermez pas la fenêtre d'impression avant d'avoir confirmé que l'impression s'est bien déroulée. Une fois confirmée, les fiches seront marquées comme imprimées et ne pourront PLUS être réimprimées.
5 Marquage irréversible et export DiameX

Description

Après 3 secondes suivant l'ouverture de la fenêtre d'impression, un popup demande : "Avez-vous terminé l'impression ?". Si l'utilisateur confirme, le système effectue automatiquement deux actions simultanées :

Action 1 : Marquage d'impression

  • fiche_imprimee passe à True
  • date_impression est rempli avec la date et l'heure actuelles
  • Cette action est IRRÉVERSIBLE (sauf intervention admin en base de données)

Action 2 : Export vers DiameX

Pour chaque fiche imprimée, une ligne est créée dans la table DiameXTemporaire avec :

  • Description : [Préfixe poste] [Nom complet]_Salaire_[Année] [Mois:02d]
    Exemple : RESP Jean DUPONT_Salaire_2025 11
  • Cat (compte_code) : Code compte salaire du poste (ex: 6211)
  • Detail : Surnom de l'employé (ex: JD) ou prénom si pas de surnom
  • ACTIV : Volet budgétaire de l'employé (ex: SOAKOJA)
  • Out (montant_out) : Salaire net arrondi au supérieur (100 Ar)
    Formule : math.ceil(salaire_net / 100) * 100
    Exemple : 449,750 Ar → 450,000 Ar
  • Date_m : Date de paiement (généralement 1er du mois)
  • Type : 'depense'
  • Statut : 'en_attente' (en attente d'envoi vers DiameX)
  • Info : 'Hydria Salaires' (source de la donnée)

Gestion des erreurs

Si le poste de l'employé n'a pas de compte_salaire défini, l'export vers DiameX échoue pour cette fiche. Dans ce cas :

  • La fiche est quand même marquée comme imprimée (pour éviter perte de traçabilité)
  • L'erreur est enregistrée dans la réponse API avec le nom de l'employé
  • Un message d'avertissement est affiché à l'utilisateur
  • L'administrateur doit corriger le compte salaire du poste et créer manuellement la ligne DiameX
Résultat : Message de confirmation affiché : "X fiche(s) marquée(s) comme imprimée(s), X ligne(s) exportée(s) vers DiameX". La liste se recharge automatiquement et les fiches imprimées disparaissent.

Détails des champs

Description

Format : [Préfixe] [Nom complet]_Salaire_[YYYY MM]
Préfixe : 4 premiers caractères du poste en majuscules
Exemple : Responsable → RESP, Technicien → TECH

Exemple : 6211 (Salaires cadres), 6212 (Salaires techniciens)

Detail (Surnom)

Source : Employe.surnom ou Employe.prenom
Usage : Identification rapide dans DiameX
Exemple : JD, MR, PR

ACTIV (Volet budgétaire)

Source : Employe.volet
Usage : Imputation analytique dans DiameX
Exemple : SOAKOJA, SHAMA, ADMINISTRATION

Out (Montant)

Calcul : math.ceil(salaire_net / 100) * 100
Arrondi : Supérieur au 100 Ar près
Exemple : 449,750 → 450,000 | 320,050 → 320,100

Date_m (Date paiement)

Source : Salaire.date_paiement
Standard : 1er du mois
Exemple : 2025-11-01 pour novembre 2025

Règles Métier CRITICAL

Marquage d'impression IRRÉVERSIBLE

Une fois qu'une fiche de paie est marquée comme imprimée (fiche_imprimee=True), elle NE PEUT PLUS être réimprimée via l'interface standard. Cette règle stricte vise à :
• Éviter les doublons de fiches de paie
• Garantir la traçabilité (une fiche = une impression = une date précise)
• Empêcher les modifications rétroactives après remise à l'employé

Solution en cas d'erreur : Un administrateur peut réinitialiser manuellement le champ fiche_imprimee à False dans la base de données Django, mais cette action doit rester exceptionnelle et être documentée.

Compte salaire obligatoire pour export DiameX

Le champ Poste.compte_salaire doit être renseigné pour chaque poste avant d'imprimer les fiches de paie. Si un employé a un poste sans compte salaire :
• La fiche sera marquée comme imprimée (pour éviter perte de traçabilité)
• Mais l'export vers DiameX échouera
• Une erreur sera retournée avec le nom de l'employé concerné
• L'administrateur devra créer manuellement la ligne DiameX après correction

Recommandation : Vérifier que tous les postes ont un compte salaire défini AVANT de lancer l'impression mensuelle.

Arrondi au supérieur (100 Ar près)

Le montant exporté vers DiameX est systématiquement arrondi au supérieur au 100 Ar près. Cette règle permet de :
• Simplifier les paiements en espèces (pas de pièces de 50 Ar)
• Éviter les problèmes de monnaie lors de remises d'argent
• Compenser d'éventuels écarts de calcul (arrondis intermédiaires)

Exemples :
• 449,750 Ar → 450,000 Ar (+250 Ar)
• 320,000 Ar → 320,000 Ar (inchangé, déjà multiple de 100)
• 287,050 Ar → 287,100 Ar (+50 Ar)

Impact financier : L'écart entre le salaire net calculé et le montant arrondi est généralement faible (0 à 99 Ar par employé) et est comptabilisé comme écart d'arrondi.

Impression en 2 exemplaires obligatoire

Le message "Imprimer en 2 exemplaires" n'est pas qu'une suggestion : il s'agit d'une obligation réglementaire et organisationnelle :
• Exemplaire 1 : Remis à l'employé avec signature pour réception
• Exemplaire 2 : Conservé dans le dossier de l'employé (archives RH)

Bonnes pratiques :
• Imprimer toutes les fiches d'un coup, puis les trier
• Faire signer un registre de remise des fiches de paie
• Archiver les exemplaires entreprise dans des classeurs mensuels
• Scanner les fiches signées pour archivage numérique (recommandé)

Questions Fréquentes (FAQ)

Que faire si je me suis trompé et que j'ai marqué des fiches comme imprimées par erreur ?

Le marquage d'impression est irréversible depuis l'interface standard. Si vous avez fait une erreur, vous devez contacter un administrateur système qui pourra :

  1. Se connecter à l'interface d'administration Django (/admin)
  2. Aller dans la section Employees > Salaires
  3. Rechercher le salaire concerné (par employé + mois)
  4. Décocher le champ Fiche imprimée
  5. Effacer le champ Date impression
  6. Enregistrer les modifications

IMPORTANT : Cette action doit être documentée (pourquoi, par qui, quand) pour maintenir la traçabilité. Si la ligne DiameX a déjà été créée, il faudra également la supprimer manuellement dans la table DiameXTemporaire.

Pourquoi le montant dans DiameX est différent du salaire net de la fiche de paie ?

Le montant exporté vers DiameX est arrondi au supérieur au 100 Ar près. Cette différence est normale et voulue. Par exemple :

  • Salaire net calculé : 449,750 Ar → DiameX : 450,000 Ar (+250 Ar)
  • Salaire net calculé : 320,050 Ar → DiameX : 320,100 Ar (+50 Ar)
  • Salaire net calculé : 287,000 Ar → DiameX : 287,000 Ar (aucun écart)

L'écart global pour tous les employés (généralement quelques milliers d'Ariary par mois) est comptabilisé comme "Écarts d'arrondi" dans un compte comptable dédié.

Raison : Simplifier les paiements en espèces (pas de pièces de 50 Ar à gérer).

Peut-on imprimer les fiches de plusieurs organisations en même temps ?

Oui, mais ce n'est pas recommandé. Voici pourquoi :

  • Les fiches de paie ont des en-têtes différents selon l'organisation (logo, nom)
  • Les comptabilités peuvent être séparées (bases DiameX différentes)
  • Le tri des fiches imprimées devient plus complexe
  • Risque de confusion lors de la distribution aux employés

Recommandation : Filtrer par organisation et imprimer séparément pour chaque organisation. Cela ne prend que quelques minutes de plus et évite les erreurs.

Comment vérifier que l'export vers DiameX s'est bien passé ?

Après avoir marqué les fiches comme imprimées, vous pouvez vérifier l'export de plusieurs façons :

  1. Message de confirmation : Vérifier que le nombre de lignes exportées correspond au nombre de fiches imprimées (ex: "12 ligne(s) exportée(s)")
  2. Interface DiameX Temporaire : Accéder à Comptabilité > Vérification et filtrer par mois/année. Les lignes doivent apparaître avec statut "en_attente"
  3. Admin Django : Aller dans /admin/accounting/diamextemporaire/ et chercher les lignes avec Info="Hydria Salaires" pour le mois concerné

Si des lignes manquent : C'est probablement dû à des postes sans compte salaire. Vérifier les erreurs dans le message de confirmation, corriger les comptes salaires, puis créer manuellement les lignes DiameX manquantes.

Que signifie le statut "en_attente" dans DiameXTemporaire ?

Le statut 'en_attente' signifie que la ligne a été créée dans Hydria mais n'a pas encore été envoyée vers le logiciel DiameX comptable.

Le workflow complet est :

  1. en_attente : Ligne créée dans Hydria après impression fiche de paie
  2. exporté : Ligne envoyée vers DiameX (via script ou export manuel)
  3. validé : Ligne validée par le comptable dans DiameX
  4. erreur : Problème lors de l'envoi vers DiameX (à corriger)

Prochaine étape : Le service comptabilité doit exporter toutes les lignes en attente vers DiameX (généralement une fois par mois, après impression de toutes les fiches de paie).

Peut-on personnaliser le format de la fiche de paie (logo, colonnes, etc.) ?

Oui, mais cela nécessite une modification du template Django. Le fichier concerné est : backend/templates/employees/fiches_paie_impression.html

Personnalisations courantes :

  • Logo : Remplacer l'image dans le header (ligne ~50)
  • Colonnes : Ajouter/supprimer des lignes dans le tableau des éléments de salaire (ligne ~100-150)
  • Couleurs : Modifier les classes Tailwind CSS
  • Signatures : Ajuster le nombre et les intitulés des zones de signature (ligne ~200)

IMPORTANT : Toute modification doit être testée sur 1-2 fiches avant impression massive. Vérifier que le rendu PDF/imprimé est correct (parfois différent de l'affichage écran).

Combien de temps faut-il conserver les fiches de paie archivées ?

Selon la législation malgache du travail, les fiches de paie et les registres de salaires doivent être conservés pendant au moins 5 ans à compter de la date d'établissement.

Recommandations de conservation :

  • Exemplaires papier : Classeurs mensuels dans une armoire sécurisée
  • Scans numériques : PDF dans un dossier partagé avec sauvegarde régulière
  • Données système : Les enregistrements dans la base de données Hydria sont conservés indéfiniment (sauf purge manuelle)

Astuce : Faire signer un registre mensuel de remise des fiches de paie par chaque employé. Ce registre fait foi en cas de litige ("l'employé affirme ne pas avoir reçu sa fiche").
