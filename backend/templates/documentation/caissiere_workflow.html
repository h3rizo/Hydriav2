Workflow Module Caissière - Retours de Tickets

  • Documentation

Vue d'ensemble

Le Module Caissière permet de traiter les retours de tickets de caisse après leur utilisation par les agents terrain.

Objectif principal

Automatiser la réception et l'enregistrement des tickets physiques (bons de livraison, avances, recettes) retournés par les agents, avec mise à jour automatique des stocks et export vers DiameX.

Transaction atomique : La validation du retour, la création de la ligne DiameX et la mise à jour du stock se font en une seule transaction pour garantir la cohérence des données.

Types de tickets traités

1. Bon de Livraison (📦)

Description : Ticket émis lors de la livraison d'équipements/fournitures par un fournisseur.

Champ clé :

PlanningDetail.numero_bon_livraison (CharField)

Actions automatiques :

  • ✅ Marquer retour=True et date_retour=now()
  • ✅ Créer ligne dans TemporaireDiameX (type='depense')
  • ✅ Impact stock : Ajouter la quantité au stock de l'équipement
  • ✅ Créer StockMovement (type='entree')

Informations affichées :

Champ Source Exemple
Fournisseur detail.fournisseur.nom JIRAMA Supplies
Équipement detail.equipement_constitutif.nom Tuyau PVC Ø20mm
Quantité detail.quantite 50
Montant detail.montant 125,000 Ar

Impact Stock - Exemple

Stock avant : 195 unités

Quantité livrée : +50 unités

Stock après : 245 unités ✅

2. Avance (💰)

Description : Ticket d'avance remis à un agent pour effectuer un achat ou un paiement.

Champ clé :

PlanningDetail.numero_bon_avance (CharField)

Actions automatiques :

  • ✅ Marquer retour=True et date_retour=now()
  • ✅ Créer ligne dans TemporaireDiameX (type='avance')
  • ❌ Pas d'impact stock (transaction monétaire)

Informations affichées :

Champ Source Exemple
Désignation detail.designation.nom Achat matériel électrique
Employé detail.planning.employe.nom_complet Victorien RAKOTO
Ouvrage detail.planning.ouvrage.nom Ambohitrimanjaka
Montant detail.montant 50,000 Ar
3. Recette / Paiement Forfaitaire (💵)

Description : Ticket de paiement collecté par un agent auprès d'un abonné.

Champ clé :

PlanningDetail.numeroDiameX (IntegerField)

Actions automatiques :

  • ✅ Marquer retour=True et date_retour=now()
  • ✅ Créer ligne dans TemporaireDiameX (type='recette')
  • ❌ Pas d'impact stock (encaissement monétaire)

Informations affichées :

Champ Source Exemple
Point d'eau detail.point_eau.nom_point_eau BP Ambohitrimanjaka Centre
Abonné detail.point_eau.parcelle.proprietaire Jean DUPONT
Montant collecté detail.montant 30,000 Ar
Période detail.planning.date Janvier 2025

Table TemporaireDiameX

Stockage temporaire des transactions avant export vers le système comptable DiameX.

Champ Type Description
id AutoField Clé primaire
planning_detail ForeignKey Lien vers le détail de planning source
type_transaction CharField avance / depense / recette / transfert
date_m DateField Date du mouvement
description CharField(255) Libellé de la transaction
compte_code CharField(50) Code du compte comptable
montant_in DecimalField Montant entrée (recettes)
montant_out DecimalField Montant sortie (dépenses/avances)

Note : Les lignes restent dans cette table jusqu'à leur export réussi vers DiameX. Le statut permet de suivre l'état de chaque ligne.

Workflow détaillé étape par étape

1 Agent terrain utilise le ticket

  • L'agent effectue une livraison, une avance ou collecte un paiement
  • Le système marque PlanningDetail.utilise = True
  • Génération automatique d'un numéro unique :
    • numero_bon_livraison pour les livraisons
    • numero_bon_avance pour les avances
    • numeroDiameX pour les recettes
  • QR Code imprimé sur le ticket physique

2 Retour du ticket à la caissière

  • L'agent retourne le ticket physique au bureau
  • La caissière accède au module : Plannings → Caissière - Retours
  • Deux méthodes possibles :
    • Scanner le QR Code avec la caméra
    • Saisir manuellement le numéro de ticket

3 Vérification et affichage

  • Appel API : POST /billing/caissiere/api/scanner-ticket/
  • Recherche dans la base de données avec le numéro
  • Vérifications automatiques :
    • ✅ Le ticket existe
    • ✅ Le ticket a été utilisé (utilise=True)
    • ✅ Le ticket n'est pas déjà retourné (retour=False)
  • Affichage des détails complets du ticket

4 Validation du retour

  • La caissière clique sur "Valider le retour"
  • Appel API : POST /billing/caissiere/api/valider-retour/
  • Transaction atomique commence (tout ou rien) :

Actions dans la transaction :

1. Mise à jour PlanningDetail :

detail.retour = True
detail.date_retour = timezone.now()
detail.save()

2. Création ligne TemporaireDiameX :

DiameXTemporaire.objects.create(
    planning_detail=detail,
    type_transaction='depense|avance|recette',
    description=...,
    montant_in=... ou montant_out=...,
    statut='en_attente',
    created_by=request.user
)

3. Si type = Bon de livraison → Impact stock :

stock.current_quantity += detail.quantite
stock.save()

StockMovement.objects.create(
    designation=detail.equipement,
    movement_type='entree',
    quantity=detail.quantite,
    reference=f'Retour {numero_ticket}'
)
Si toutes les opérations réussissent, la transaction est validée. Sinon, tout est annulé (rollback).

5 Export périodique vers DiameX

  • Script ou API périodique (à implémenter)
  • Récupère toutes les lignes avec statut='en_attente'
  • Envoie vers le système DiameX externe
  • En cas de succès :
    • statut='envoye'
    • date_envoi_diamex=now()
  • En cas d'erreur :
    • statut='erreur'
    • erreur_message = détails de l'erreur
    • Retry manuel ou automatique possible
À implémenter : L'export automatique vers DiameX n'est pas encore développé. Les lignes s'accumulent dans la table temporaire.

Règles CRITICAL

1. Un ticket ne peut être retourné qu'une seule fois

Le champ retour passe de False à True de manière irréversible. Aucun mécanisme d'annulation prévu.

2. Transaction atomique obligatoire

L'utilisation de @transaction.atomic() garantit que si une étape échoue (marquer retourné, créer ligne DiameX, MAJ stock), TOUTES les étapes sont annulées. Pas de demi-état.

3. Impact stock uniquement pour les livraisons

Les avances et recettes sont des transactions monétaires sans mouvement physique. Seuls les bons de livraison affectent le stock.

4. Export DiameX manuel pour l'instant

L'export automatique vers DiameX n'est pas encore implémenté. Les lignes s'accumulent en statut='en_attente' jusqu'à export manuel.

5. Sécurité : Authentification requise

Toutes les vues et APIs du module caissière nécessitent @login_required. Seules les caissières authentifiées peuvent traiter les retours.

FAQ - Questions fréquentes

1. Que se passe-t-il si le QR code est illisible ?

Utilisez l'onglet "Saisie manuelle" pour entrer le numéro de ticket affiché sur le document. Le système accepte aussi les scans avec douchette laser.

2. Peut-on annuler un retour validé ?

Non. Une fois le retour validé, le champ retour=True est irréversible. En cas d'erreur, contactez un administrateur pour modification manuelle dans la base de données.

3. Combien de temps les lignes restent en "En attente" ?

Les lignes restent en statut='en_attente' jusqu'à ce qu'un export manuel ou automatique les transmette vers DiameX. L'export automatique n'est pas encore implémenté (prochaine étape).

4. Que faire si le stock devient négatif après un retour ?

Le retour d'un bon de livraison ajoute au stock (+quantité). Le stock ne devrait jamais devenir négatif suite à un retour. Si c'était déjà négatif avant, le retour améliore la situation.

5. Peut-on traiter plusieurs tickets d'affilée ?

Oui, après validation d'un ticket, vous pouvez immédiatement scanner/saisir le suivant. Le système réinitialise l'interface pour le prochain ticket.

6. Qui reçoit les notifications d'erreurs d'export ?

Pour l'instant, il n'y a pas de système de notifications automatiques. Les lignes en erreur doivent être consultées manuellement dans l'interface. Fonctionnalité à implémenter dans une version future.
